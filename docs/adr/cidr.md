# ADR 0003: Схема CIDR та кількість зон доступності

## Контекст

У M2 з'являються координатор і шарди, у M3 кожен шард реплікується на 3+ вузли, далі додаються моніторинг і автоскейлінг. Для кворуму з трьох реплік їх потрібно розміщувати в різних AZ. Середовище — AWS sandbox з обмеженим бюджетом.

Що показала розвідка в регіоні `us-east-1`: доступні шість AZ (`us-east-1a`–`f`) зі станом `available`. У регіоні вже є default VPC з діапазоном `172.31.0.0/16`.

## Розглянуті варіанти

**Діапазон VPC.** `10.0.0.0/16` — найпоширеніший приклад із підручників, тому може збігатись з чужими мережами. `172.16.0.0/12` перетинається з default VPC та мережами Docker, `192.168.0.0/16` — з домашніми мережами. Приватний блок у `10.0.0.0/8` з нетиповим другим октетом не має відомих перетинів.

**Розмір VPC.** `/16` — найбільший дозволений блок і дає колосальний запас: десятки вузлів проти десятків тисяч адрес. Меншу мережу довелося б розширювати вторинним CIDR-блоком, що ускладнює план адресації.

**Кількість AZ.** Дві зони дають мінімальну відмовостійкість, але три репліки лягають як 2+1, і втрата зони з двома репліками руйнує кворум. Три зони дають розкладку 1+1+1: втрата будь-якої однієї зони залишає дві репліки, кворум зберігається.

## Рішення

VPC `10.7.0.0/16` і три AZ. У кожній зоні по одній публічній і одній приватній підмережі `/24`:

| Тип | Підмережі |
|---|---|
| Публічні | `10.7.0.0/24`, `10.7.1.0/24`, `10.7.2.0/24` |
| Приватні | `10.7.10.0/24`, `10.7.11.0/24`, `10.7.12.0/24` |
| Резерв | `10.7.20.0/24` і далі |

Третій октет читається як тип підмережі: 0–9 публічні, 10–19 приватні, 20 і далі резерв. Імена зон беруться динамічно (`!GetAZs`), а не прописуються жорстко. NAT не плануємо.

## Обґрунтування

Діапазон `10.7.0.0/16` не перетинається з default VPC, Docker і типовими домашніми мережами. Три AZ потрібні для відмовостійкості на рівні M3 (1+1+1), а підмережі в мережевому шарі безкоштовні: платити доводиться лише за те, що в них запущено. NAT не потрібен, бо за завданням приватні підмережі призначені лише для внутрішнього доступу.

## Наслідки

Шість підмереж, із 256 можливих блоків `/24` зайнято шість (2,3%). Кожна підмережа має 251 доступну адресу, бо AWS резервує п'ять. Без NAT вузли в приватних підмережах не матимуть виходу в інтернет, тож доступ до сервісів AWS (наприклад, CloudWatch у M4) доведеться організовувати через VPC endpoints; це рішення належить M2. Міжзонний трафік реплікації тарифікується, але на обсягах цього проєкту це незначно. Основний CIDR VPC змінити неможливо без перестворення мережі, тоді як додати підмережі чи зони пізніше можна завдяки резерву. Якщо потрібно переглянути це рішення, створюється новий ADR зі статусом «замінює 0003».
